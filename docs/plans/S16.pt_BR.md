# S16 — Observabilidade: traces OTel, métricas Prometheus, logs Loki, dashboard Grafana

Track C, transversal, repo `zero-bridge` → `bridge/obs/` (go.mod próprio).

## Alvo

`grafana/otel-lgtm` (Loki + Tempo + store compatível Prometheus + Grafana) atrás de um `otel/opentelemetry-collector-contrib` cujos receivers OTLP estão publicados em `4317` (gRPC) e `4318` (HTTP). O bridge envia OTLP para o collector local; nunca escuta telemetria em endereço não-loopback.

## Sinais

- **Traces** (Tempo; Jaeger UI opcional sobre os mesmos dados): um span por requisição HTTP (template da rota, método, status), por chamada ACP (`session/new|load|resume|prompt|set_mode|list`), por requisição de permissão (decisão, tempo até decisão), por tentativa de login.
- **Métricas** (Prometheus): contagem/latência histograma/erros por template de rota; prompts em voo; SSE streams ativas e eventos descartados; requisições de permissão por decisão e expiração; eventos de auth (login ok/fail/429, falha Bearer, logout, sessão expirada/evictada — par com S14b); child `zero acp` up/restarts; latência de chamada ACP; contagem de avisos zero; runtime Go (goroutines, heap).
- **Logs** (Loki): JSON estruturado (`log/slog`) através do redator existente, com `trace_id`/`span_id` para que o Grafana ligue log ↔ trace.

## Regras duras

- **Nenhum segredo ou conteúdo em telemetria:** nunca texto do prompt, `rawInput` de ferramenta, caminhos de arquivo, tokens, cookie ou session ids completos. Atributos vêm de allowlist explícita; labels usam templates de rota, nunca paths crus.
- **Baixa cardinalidade** nos labels de métricas (sem session/request ids).
- **Endpoint do exportador deve ser loopback** a menos que flag explícita permita o contrário (exit 2 caso contrário); telemetria desligada por padrão (`--otlp-endpoint` vazio).
- Custo zero: collector local apenas.
- **Definição de pronto para cada slice posterior (S6b, S7, S8-S10):** cada nova rota/evento envia seu span, métrica e campos de log.

## Decisão

**Padrão (recomendado):** manter o core apenas stdlib. Uma interface `Observer` pequena vive em `bridge/`; o SDK Go do OpenTelemetry é importado apenas por um módulo/binário separado (`bridge/obs`, go.mod próprio), de modo que `go build ./...` do bridge continua com zero deps de terceiros.

## Entregáveis

- Instrumentação + flags `--otlp-endpoint`, `--otel-service`, taxa de amostragem (finita, default documentado).
- Dashboard Grafana JSON provisionado do repo (`deploy/grafana/zero-bridge.json`): tráfego/latência/erros, sessões e prompts, funil de permissão, eventos de auth, saúde do agente, runtime, painel de logs e links de trace.
- Regras de alerta: pico de falha de auth, agente down, taxa de expiração de permissão.
- Docs EN/pt_BR com snippet do collector e como importar o dashboard.
- Evidência: transcript mostrando um prompt produzindo trace no Tempo, métricas no store e linha de log correlacionada (comandos mostrados primeiro).
