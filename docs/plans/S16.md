# S16 — Observability: OTel traces, Prometheus metrics, Loki logs, Grafana dashboard

Track C, cross-cutting, repo `zero-bridge` → `bridge/obs/` (own go.mod).

## Target

`grafana/otel-lgtm` (Loki + Tempo + Prometheus-compatible store + Grafana) behind an `otel/opentelemetry-collector-contrib` whose OTLP receivers are published on `4317` (gRPC) and `4318` (HTTP). The bridge pushes OTLP to the local collector; it never listens for telemetry on a non-loopback address.

## Signals

- **Traces** (Tempo; Jaeger UI optional over the same data): one span per HTTP request (route template, method, status), per ACP call (`session/new|load|resume|prompt|set_mode|list`), per permission request (decision, time to decision), per login attempt.
- **Metrics** (Prometheus): request count/latency histogram/errors by route template; in-flight prompts; active SSE streams and dropped events; permission requests by decision and expiry; auth events (login ok/fail/429, Bearer failure, logout, session expired/evicted — pairs with S14b); child `zero acp` up/restarts; ACP call latency; zero warnings count; Go runtime (goroutines, heap).
- **Logs** (Loki): structured JSON (`log/slog`) through the existing redactor, with `trace_id`/`span_id` so Grafana links log ↔ trace.

## Hard rules

- **No secrets or content in telemetry:** never prompt text, tool `rawInput`, file paths, tokens, cookie or full session ids. Attributes come from an explicit allowlist; labels use route templates, never raw paths.
- **Low cardinality** on metric labels (no session/request ids).
- **Exporter endpoint must be loopback** unless an explicit flag allows otherwise (exit 2 otherwise); telemetry is off by default (`--otlp-endpoint` empty).
- Zero cost: local collector only.
- **Definition of done for every later slice (S6b, S7, S8-S10):** each new route/event ships its span, metric and log fields.

## Decision

**Default (recommended):** keep the core stdlib-only. A small `Observer` interface lives in `bridge/`; the OpenTelemetry Go SDK is imported only by a separate module/binary (`bridge/obs`, own `go.mod`), so `go build ./...` of the bridge keeps zero third-party deps.

## Deliverables

- Instrumentation + `--otlp-endpoint`, `--service-name`, sampling ratio flag (finite, documented default).
- Grafana dashboard JSON provisioned from the repo (`deploy/grafana/zero-bridge.json`): traffic/latency/errors, sessions and prompts, permission funnel, auth events, agent health, runtime, logs panel and trace links.
- Alert rules: auth failure spike, agent down, permission expiry rate.
- Docs EN/pt_BR with the collector snippet and how to import the dashboard.
- Evidence: transcript showing a prompt producing a trace in Tempo, metrics in the store and a correlated log line (commands shown first).

## Order

S14 → S14b → **S16 (this)** → S6b → S7. Instrumenting before the new surface lands keeps later slices from retrofitting.
