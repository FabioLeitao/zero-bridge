# S23b — Desktop shell: tray, permission notifications, folder picker

Track D, repo `FabioLeitao/zero-bridge-desktop`.

## Scope

- Tray icon with show/hide and quit; window state restored.
- Native notification when the bridge reports a pending permission request while the window is hidden. Text only: the tool title already shown on the permission card, nothing from agent output beyond it. Clicking focuses the window on that card.
- Folder picker for a new session's workspace, validated against the bridge's `--workspace-root`; a dropped folder is accepted the same way.
- Optional start at login; single-instance lock; deep link `zero-bridge://` is validated and not enabled until there is a use for it.

## Acceptance

- Hostile tool title is shown as text in the notification; the picker refuses a path outside the workspace root; second launch focuses the first window.

## Dependencies

- S23a (this issue's parent shell), #2 (S6b).

## Status

- Implemented in `FabioLeitao/zero-bridge-desktop` main branch.
- TrayController, PermissionNotifier, FolderPicker added with unit tests.
- IPC channels exposed via preload: `zb:permission-request`, `zb:pick-workspace`, `zb:folder-drop`, `zb:fetch-workspace-roots`, `zb:permission-focus`.
- Main process wires tray, notifier, folder picker to Electron window.
- Single-instance lock enforced via `app.requestSingleInstanceLock()`.
- Folder picker validates against bridge `/v1/capabilities` workspaceRoots.
