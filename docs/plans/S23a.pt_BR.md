# S23a — Scaffold do shell desktop, sidecar, hardening

Track D, repo `FabioLeitao/zero-bridge-desktop`.

## Escopo

- Scaffold do repositório: TypeScript, Electron, lockfile, install scripts bloqueados, `npm audit` no gate, MIT, READMEs EN/pt_BR, CONTRIBUTING e AGENTS copiados das regras do bridge (commits assinados, merge commits apenas).
- Processo principal inicia `zero-bridge` como sidecar (array argv, sem shell) com token por lançamento escrito em arquivo `0600` ou mantido via `safeStorage`; porta loopback efêmera (ou socket S21 quando disponível); aguarda `/health`; uma janela carrega a UI do bridge; sair para o sidecar pelo pid gravado.
- Hardening exatamente como em #23: `contextIsolation`, `sandbox`, sem `nodeIntegration`, preload mínimo, CSP estrito, navegação e window-open negados fora da origem do sidecar, requisições de permissão da página negadas.
- Caminhos de falha do sidecar: crash, porta em uso, arquivo de token inválido, agente não encontrado; cada um mostra um estado de erro na janela, nunca janela em branco.

## Aceitação

- `npm test` testes unitários para o launcher e allowlist de origem; teste de fumaça que inicia o shell contra agente fake, carrega a UI e sai limpo sem processo residual.
- Nenhum segredo em argv, logs, URL ou renderer; um teste grepa a linha de comando do sidecar e o log.

## Dependências

- S6b modelo de workspace; S21 opcional mas preferido (Unix socket).
