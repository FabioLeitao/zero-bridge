# S25 — Image attachment with limits

Track D, repo `zero-bridge` → `bridge/web/`, `bridge/internal/server/`.

## Scope

`promptCapabilities.image` is read already (S19). When true, the composer accepts a pasted or dropped image and sends it as an ACP image content block.

Limits (all finite, configurable, with a hard cap):
- 4 MiB decoded per image, hard cap 16 MiB
- 4 images per prompt
- The HTTP body cap includes the 4/3 base64 expansion, so four images at the decoded cap fit. A fifth image is `too many images`. A larger decoded image is `exceeds limit`. A body past the cap is `body too large`
- MIME allowlist (PNG, JPEG, WebP, GIF; no SVG)
- Magic-byte check
- No EXIF-based rendering
- Nothing written to disk by the bridge
- No image data in logs or audit lines
- Hidden when the agent does not advertise image support

## Acceptance

- Oversize and wrong-type files are refused with a clear message
- A polyglot or SVG is refused
- The control is hidden for an agent without the capability
- Mutant that drops the size cap dies
- The headless check runs with a local fake agent only (no model call)

## Dependencies

S19 (capability gate, promptCapabilities), S6b (workspace management).
