# S25 — Anexos de imagem com limites

Track D, repo `zero-bridge` → `bridge/web/`, `bridge/internal/server/`.

## Escopo

`promptCapabilities.image` já é lido (S19). Quando verdadeiro, o compositor aceita imagem colada ou solta e a envia como bloco de conteúdo ACP de imagem.

Limites (todos finitos, configuráveis, com teto rígido):
- 4 MiB decodificados por imagem, teto rígido 16 MiB
- 4 imagens por prompt
- O teto do corpo HTTP inclui a expansão base64 de 4/3, então quatro imagens no teto decodificado cabem. A quinta imagem é `too many images`. Uma imagem decodificada maior é `exceeds limit`. Um corpo acima do teto é `body too large`
- Allowlist MIME (PNG, JPEG, WebP, GIF; sem SVG)
- Verificação de magic bytes
- Nenhum processamento baseado em EXIF
- Nada escrito em disco pelo bridge
- Nenhum dado de imagem em logs ou linhas de auditoria
- Escondido quando o agente não anuncia suporte a imagem

## Aceitação

- Arquivos acima do limite e de tipo errado são recusados com mensagem clara
- Polyglot ou SVG são recusados
- O controle fica escondido para agente sem a capacidade
- Mutante que remove o teto de tamanho morre
- O teste headless roda com fake agent local apenas (sem chamada a modelo)

## Dependências

S19 (gate de capacidade, promptCapabilities), S6b (gerenciamento de workspace).
